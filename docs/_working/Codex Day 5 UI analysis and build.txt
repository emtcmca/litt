Codebase Read
The repo is already well past the “docs only” state in AGENTS.md: backend, tests, Firestore-facing tools, agents, brief assembly, and a React dashboard are present. Architecturally, the strongest through-line is excellent: deterministic Python owns state, audit, routing, scrubber logic, demo readiness, and brief assembly; agent code stays thin. That matches Litt’s core promise.

The UI is centered correctly on the Daily Closeout Brief in DailyCloseoutBrief.tsx. The design docs in /design are also unusually coherent for a first pass: “operational calm,” “defensible audit trail,” “attorney remains in control,” and “precise legal language” are the right brand pillars.

Brand Voice
I’d sharpen Litt’s voice as:

Calm command, not cheerful assistance.

Litt should sound like a senior ops partner who knows what matters and has receipts. Avoid assistant-y phrasing like “I found…” or “Looks like…”. Prefer:

“Deadline requires confirmation”
“Budget threshold crossed”
“Narrative blocks approval”
“Action logged”
“Dismissal reason required”
The product should almost never sound impressed with itself. The trust move is restraint.

Visual Direction
The current design system is on the right path: muted legal/fintech palette, compact cards, semantic status colors, no decorative fluff. I’d keep that.

Where I’d refine:

Make the audit trail a first-class visual motif.
The audit drawer is a great product signature. Bring “logged / source / actor / timestamp” into more cards so defensibility is visible before the user clicks.

Add an executive triage strip above the cards.
Something like: 1 critical · 2 billing blocks · $11.7k WIP · generated 4:30 PM. This gives the attorney a 5-second read before the detailed queue.

Use a “decision packet” card anatomy.
Every item should answer, in order: status, what happened, why it matters, evidence/source, requested action. This mirrors legal judgment flow.

Make primary actions visually stronger.
--color-background-info is currently a pale blue, so primary buttons can feel soft. For consequential actions, consider a stronger blue token like --color-ramp-blue-600 with white text, while keeping secondary actions quiet.

Reduce all-caps except machine labels.
The docs say sentence case, but some implemented/demo surfaces use uppercase labels and Tailwind defaults. Keep enum/status badges uppercase because they read as system states; keep human UI text sentence case.

Style Guide Notes
A few inconsistencies to resolve in the design docs:

Litt-Brand-Guidelines.md says no font weight above 500, but Litt-Critical-Alert-Enhancement.md allows 600 for critical badges. I’d explicitly allow 600 only for red critical badges.
The docs say “never hardcode colors,” but the React implementation hardcodes many semantic hexes in DailyCloseoutBrief.tsx and modal files. I’d add semantic badge/accent tokens so implementation can stay tokenized.
App.css still contains Vite starter styles. It should be deleted or replaced before polish; it dilutes the product’s seriousness.
EmailPreview.tsx has a deliberately plaintext/legal memo feel, which is promising, but it drifts from the main design system with Tailwind grays, uppercase headers, and a purple client-silence accent. I’d make the email preview feel like the email version of the same brand, not a separate artifact.
Layout And Flow
The single-page modal workflow is the right demo choice. To improve flow:

Put sections in strict risk order: critical deadlines, billing blocks, budget risks, client silence, anomalies/routine.
Let resolved items collapse into a “session activity” tray, which you already started. That’s very on-brand.
For each modal, lead with consequence and audit impact: “This will mark the deadline attorney-confirmed and create an audit event.”
Consider changing “Run sweep” to “Refresh brief” or “Run operations sweep.” “Run sweep” is engineer-facing; “Refresh brief” is attorney-facing.
Aesthetic North Star
Litt should feel like:

Linear’s restraint
Stripe’s clarity
a docketing system’s precision
a legal memo’s evidentiary discipline
Not: chatbot, startup dashboard candy, or generic admin panel.

The most distinctive UI idea is to make every action feel like it produces a defensible record. If the interface consistently shows “why this surfaced” and “what will be logged,” Litt’s brand will feel much more ownable than just “AI dashboard for law firms.”

Yes, that changes the design target.

For a normal legal SaaS product, Litt should be restrained and nearly invisible. For a hackathon, it still needs legal seriousness, but it also needs a memorable “oh, I get it” moment within 10 seconds.

My revised take: keep the brand voice calm and precise, but make the UI more cinematic around the core ritual.

The judging-facing design goal should be:

“This is not another dashboard. This is the end-of-day operating room for a small law firm.”

I’d push the UI in three ways:

Open with a high-impact command view
The first screen should immediately show the Daily Closeout Brief as a mission-control surface: critical deadline, blocked billing, budget risk, client silence, audit trail. Judges should understand the entire product without narration.

Make the audit trail visually dramatic
When the user confirms a deadline or approves an item, show a polished audit drawer/slideover with:

action taken
before/after state
attorney
timestamp
immutable audit event ID
This is the “judge remembers it” moment. The defensibility claim becomes visible.

Use more deliberate hierarchy
The current design is calm, but maybe too quiet for a demo. Critical cards should feel unmistakable. The top summary should feel like a live operational briefing: 1 critical risk, $11,700 WIP, 5 actions pending, audit-ready.

I would not make it flashy in the generic hackathon sense. No gradients, mascot, oversized hero, or AI sparkle. The impressive version of Litt is “controlled intensity”: sharp, dense, high-trust, with one or two beautifully staged moments.

Best aesthetic direction:

Legal command center
Fintech-grade polish
Evidence-first interactions
Demo-friendly visual reveals
The strongest UI idea I’d prioritize: a “Closeout Brief timeline” where each section collapses into a vertical sequence of decisions, and resolving an item visibly appends to a session audit log. That gives judges a product story: Litt finds risk, asks for attorney judgment, records the decision, and proves what happened.
